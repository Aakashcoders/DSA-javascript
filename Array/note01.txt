Step-by-Step Logic Breakdown
Maan lo arr3 me pehle se [10, 20, 30, 40, 50, 60] hai (jinki length = 6 hai). Now see what happens inside the loop for arr2 = [70, 80, 90, 100]:

i = 0 Step:

arr3.length is 6. Index = 6 + 0 = 6.

arr3[6] = 70.

Current arr3 array: [10, 20, 30, 40, 50, 60, 70] (Ab length 7 ho gayi!)

i = 1 Step:

Ab arr3.length 7 ho chuki hai!

Index formula: arr3.length + i = 7 + 1 = 8.

Code ne element ko index 8 par insert kar diya (arr3[8] = 80).

Result: Index 7 skip ho gaya! JS ne automatically index 7 ko empty slot bana diya.

i = 2 Step:

Ab arr3.length 9 ho chuki hai!

Index: 9 + 2 = 11.

arr3[11] = 90.

Result: Index 9 aur 10 skip ho gaye (empty × 2).

Jab bhi aap loop me arr3.length + i use karte ho, toh arr3.length har iteration par badhti hai AUR i bhi badhta hai, jisse index double speed se aage jumps marne lagta hai!

Meaning: Jab kisi JavaScript array ke beech me gaps ya unassigned indices hote hain (e.g. empty × 2), toh use computer science terminology me Sparse Array bolte hain.

Binary Search is an efficient searching algorithm used in Data Structures and Algorithms (DSA) that finds the position of a target value within a sorted array by repeatedly halving the search space. Instead of checking elements one by one like Linear Search, it uses a divide-and-conquer strategy, achieving an incredibly fast time complexity of \(O(\log n)\)
Linear search (also known as sequential search) is the simplest searching algorithm in Data Structures and Algorithms (DSA) that finds the position of a target value within a list by checking each element sequentially from start to finish. It starts at the first element, compares it to the target, and moves to the next element until a match is found or the entire collection is exhausted

Asymptotic analysis is a mathematical framework used to measure and describe how the performance of a program (both runtime and memory usage) scales as the input size (n) grows toward infinity. In JavaScript, it allows developers to evaluate code efficiency independently of the engine (e.g., V8), hardware, or CPU load
The Three Core NotationsWhen analyzing JavaScript algorithms, we look at the theoretical number of operations executed using three primary asymptotic bounds
Big-O (O): Represents the upper bound (worst-case scenario). It guarantees the code won't perform worse than this limit. This is the industry standard for code reviews and interviews
Big-Omega (Ω): Represents the lower bound (best-case scenario). It is the absolute fastest the code can run under ideal inputs.
Big-Theta (Θ): Represents a tight bound. It applies when the best-case and worst-case complexities grow at the exact same rate

1. Core Logic aur Intuition
Asymptotic analysis ka main maqsad yeh samajhna hai ki koi algorithm input size (n) badhne ke saath kaise perform karti hai. Hum code ko kitne seconds mein chala, yeh nahi napte; balki hum yeh dekhte hain ki number of operations (code ki kitni lines execute ho rahi hain) input ke hisaab se kaise grow karte hain. Yeh hamein decide karne mein help karta hai ki bade data sets (jaise 1 crore records) ke liye kaunsa algorithm best rahega.
2. Step-by-Step Logic
Input Dependency: Algorithmic complexity puri tarah se input size (n) par depend karti hai.
Constants ko Ignore karna: Analysis ke waqt hum constant factors (jaise 5 ya 10 extra lines) ko ignore kar dete hain. Jab input size bohot bada (infinity) ho jata hai, toh yeh constants performance par koi khas asar nahi daalte.
Dominant Term: Hum hamesha sabse badi term (jaise n ki power 2) ko focus karte hain, kyunki wahi decide karti hai ki algorithm ka worst-case performance kaisa hoga.

Time aur Space Complexity
Time Complexity: Yeh input size ke growth rate ko measure karti hai. Ismein hum Big O notation ka use karte hain jo 'Worst Case' scenario batata hai, yani algorithm zyada se zyada kitna slow ho sakti hai.

Bubble Sort algorithm ko JavaScript ke zariye samajhaya gaya hai. Bubble Sort ek basic sorting technique hai jisme hum elements ko compare karke unhe sahi jagah par arrange karte hain.

1. Core Logic aur Intuition
Bubble Sort ka main logic ye hai ki hum array ke adjacent (saath wale) elements ko compare karte hain. Agar left wala element right wale se bada hai, toh hum unhe swap (apas me badal) dete hain. Is process ko baar-baar repeat karne se, har iteration ke baad sabse bada element apne sahi position (end of array) par 'bubble' hokar pahunch jata hai.

2. Step-by-Step Logic
Nested Loops ka istemal: Isme do loops chalaye jate hain. Outer loop handle karta hai ki hum kitni baar poore array ko scan kar rahe hain.
Comparison: Inner loop array ke elements ko 0th index se start karke compare karta hai. Har step par current element ko next element se compare kiya jata hai.
Swapping: Agar current element > next element hai, toh ek temporary variable ki madad se dono ki values swap kar di jati hain.
Sorting completion: Jaise-jaise loops chalte hain, array ke end me bade numbers jama hote jate hain, aur end me poora array sorted mil jata hai.
3. Concrete Example: Dry Run
Maano hamare paas array hai: [40, 12, 25]

Pass 1:
Compare 40 aur 12: 40 bada hai, swap karo. Array ban gaya: [12, 40, 25]
Compare 40 aur 25: 40 bada hai, swap karo. Array ban gaya: [12, 25, 40]
Ab 40 apni sahi jagah (last) par pahunch gaya hai.
Pass 2:
Compare 12 aur 25: 12 chota hai, koi swap nahi.
Array ab fully sorted hai: [12, 25, 40]
